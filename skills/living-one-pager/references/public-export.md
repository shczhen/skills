# Public or anonymized exports

Apply this guidance when the requested output is public, reusable, or anonymized. Ordinary private records can retain authorized source detail.

Create a separate public copy or package. Keep necessary private evidence in its existing scope. Traceability in a public artifact can use a self-contained synthetic source note or an authorized public source; it must not depend on an inaccessible internal URL.

Inspect the files actually being exported for real names, handles, emails, organization/project/customer names, internal domains and URLs, repository/remotes, local machine paths, credentials, identifiers, logs, and revealing metadata. Removing names alone is insufficient when a combination of details identifies the source.

Use neutral roles, clear placeholders, or entirely synthetic examples. Mark synthetic input and output as fictional. Preserve the decision logic but do not present changed numbers, dates, claims, or quotations as real evidence. If a necessary fact cannot be safely generalized, omit it from the public copy and explain the limit.

Check supporting files, comments, archives, hidden files, links, and examples as well as the main document. Include only intended public files; do not copy raw conversations, internal research, or validation logs by default. Public packaging does not authorize a push, upload, or announcement.
